# 比赛现场演示指南

## 演示目标

让评委在 2 分钟内看到系统不是概念，也不是后台功能堆叠，而是能够根据数据完成“预测 -> 补货 -> 分仓 -> 仿真评估”的闭环。

## 演示前准备

在项目根目录运行：

```bash
PYTHONPATH=src python -m overseas_inventory.demo
```

确认生成：

- `output/replenishment_plan.md`
- `output/replenishment_plan.json`
- `output/dashboard.html`

## 演示流程

### 1. 展示输入数据

打开 `data/sample_network.json`，说明系统输入包括：

- SKU：品类、包装数、单位利润、服务等级。
- 海外仓：国家、区域、处理能力、尾程能力。
- 运输链路：库存池到各海外仓的提前期和成本。
- 库存状态：现货、在途、已分配。
- 需求历史：SKU-仓维度每日销量。

讲解重点：这些都是跨境电商企业常规系统中可获得的数据。

### 2. 展示系统运行

运行命令后说明：

```bash
PYTHONPATH=src python -m overseas_inventory.demo
```

系统完成五件事：

1. 预测各 SKU 在各海外仓的未来 P50/P80/P95 需求。
2. 判断是否低于补货点并生成建议补货量。
3. 从全球库存池按优先级分配库存。
4. 生成履约仓和跨仓缺口说明。
5. 用 90 天仿真对比传统独立备货和智能库存池方案。

### 3. 展示输出结果

优先打开 `output/dashboard.html`，再打开 `output/replenishment_plan.md` 作为明细说明。驾驶舱重点页依次讲：

- 库存池总览：各海外仓风险颜色和核心指标。
- AI 需求预测：日均预测、P80、P95 和风险状态。
- 缺货预警：红黄风险、紧急度和未满足缺口。
- 补货优化：库存位置、补货点、目标库存和建议补货。
- 补货审批：高金额或高风险补货进入审批队列。
- 分仓履约：库存池分配数量、运输方式、缺口、到仓天数和优先级。
- 库存池水位：SKU 可分配、已分配和剩余水位。
- 仓网地图：海外仓坐标、入仓压力和风险状态。
- 仿真评估：传统独立备货 vs 智能库存池方案。

讲解重点：系统不是只告诉企业“要补货”，而是解释“为什么补、补多少、先补哪里、缺口怎么处理”，并证明比 baseline 更好。

## 推荐答辩话术

如果评委问“AI 在哪里”：

> 当前原型采用可解释的趋势加权预测作为基线模型，重点是验证 AI 预测如何进入供应链决策闭环。真实落地时，可以将该模块替换为 LightGBM、Prophet 或深度时序模型，但补货点、库存池和分仓策略仍然保持一致。

如果评委问“和普通 ERP 有什么区别”：

> 普通 ERP 更偏记录库存和执行订单，本项目面向计划决策。它把多仓库存抽象成全球库存池，并基于预测和优先级主动告诉计划员应该补哪里、补多少、为什么。

如果评委问“如何落地”：

> 第一步不直接自动下发，而是作为计划建议模块接入企业 OMS/WMS/ERP；第二步引入审批；第三步再根据采纳率和执行反馈逐步自动化。

如果评委问“库存池不够怎么办”：

> 系统会按优先级分配，未满足部分明确列为缺口，进入采购、空运加急或跨仓调拨队列，避免平均分配导致关键区域仍然缺货。

如果评委问“怎么证明有效”：

> 我们不只展示预测误差，而是做 90 天滚动仿真。传统方案按国家仓独立备货，智能方案使用全球库存池和预测优化。系统直接对比 Fill Rate、缺货率、配送时效、平均库存和利润。
