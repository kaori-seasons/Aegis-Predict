# v0.8.0 管理工作台：对账差异、主数据映射与成员权限

日期：2026-11-16。对应本轮生产实现与合成数据验证；第17篇保留v0.7.0历史证据。

## 页面与阅读路径

五个业务页面及手机六项主导航保留。数据源管理区新增“连接与来源 / 对账差异 / 主数据映射 / 成员与权限”页签，按权限显示；直接打开无权限页面也受API限制。沿用白底、细线、克制状态色，管理页提供更宽的工作区，列表每页50条，查询条件在翻页时保留。

管理脚本随Python包发布，使用内容摘要更新缓存版本，继续复用Google会话、CSRF、提交防重、过期会话清理及审计。对话框具名、表单有标签和键盘焦点；没有新增前端令牌存储或独立管理员密码入口。

## 对账差异处置

- 列表对每个批次只取最新检查，分页展示缺失/多出/变化数量。详情保留原始对账状态与源/本地摘要、scope、最近20次复核和最近50条处置记录。
- 新检查保存每类最多20个差异预览，只展示允许的库存/需求字段与源版本，其他原始字段值不回显。历史检查继续显示最多100个差异键，不伪造历史源内容。
- 新增 `reconciliation_case` 保存批次处置状态、负责人、解决检查和修订号。修改须带预期修订号及说明，旧版本409，所有说明写入不可变审计。
- 负责人必须是本租户有效、具有接入管理权限的全地点成员。解决必须关联最新 `matched` 检查，同来源/数据流/scope；跨批次修正还须使用当前完整批次并覆盖原时间窗口。旧通过结果、不同来源结果不能关闭差异。
- 后续同批次复核再出现差异，已解决处置自动重新打开并递增修订号。处置状态始终独立于源证据，不提供“人工豁免对账”功能，发布门禁仍读取权威批次的最新实际对账。

## 主数据映射

按来源系统/外部标识搜索，按商品/仓库与待确认/已确认/自动匹配筛选。确认弹窗通过服务端查找有效标准代码，使用预期更新时间防止并发覆盖，记录映射依据。

确认后仅将该来源最多500条未映射隔离记录重新排队，返回真实排队数量；Worker再次规范化并更新批次，其他异常仍会重新隔离，不自动接受质量异常。列表“已确认”只说明映射完成，不能当作规范化成功；后续结果在数据源隔离列表/批次中核对。

已确认映射不能直接改指不同商品或仓库，因为既有规范事实不会随一次标识修改自动重建。纠错需要经过审核的主数据重建流程；本轮未实现此重建界面。新增标准商品/仓库仍通过已有主数据导入接口完成，页面只确认已有有效目标。

## 成员与权限

- 分页查询成员，显示角色、有效权限、地点范围、启停状态与Google是否绑定，不返回密码摘要、会话令牌或Google subject。
- 新增成员可绑定经可信流程取得的Google subject。Google模式未提供密码时生成不可知随机密码；未绑定身份的成员无法通过Google登录。密码模式兼容原API并要求显式初始密码。系统不发送邀请邮件。
- 修改姓名、角色、启停或范围需提供最新 `updated_at` 和原因；修改及显式会话撤销均留痕。角色或状态改变后全部旧会话失效，下次请求401。
- 成员写入按租户行锁串行化，最后一位有效全地点管理员不能被停用/降权。Google模式只将已绑定Google身份的其他管理员视为可接替者；并发两人降权也必须留下一位管理员。
- 指定地点仅接受本租户有效地点；租户管理员必须全地点范围。现有业务API仍拒绝受限地点用户，页面明确说明该限制，没有默默扩大权限。

## 接口与权限

| 接口 | 权限与用途 |
| --- | --- |
| `GET /workspace/reconciliations` | `data:view`；每批次最新检查、分页及差异状态筛选 |
| `GET /data/reconciliations/{id}` | `data:view`；安全预览、历史与处置记录 |
| `GET /workspace/reconciliation-assignees` | `integration:connection:edit`；可分配成员 |
| `POST /data/batches/{id}/disposition` | `integration:connection:edit`；带修订号的处置更新 |
| `GET /workspace/mappings`、`GET /workspace/catalog/search` | `integration:connection:view`；分页映射与有效主数据检索 |
| `POST /mappings/{id}/resolve` | `integration:mapping:resolve`；确认与有限量重放 |
| `GET/POST /users`、`PATCH /users/{id}` | `user:manage`；成员管理 |
| `POST /users/{id}/revoke-sessions`、`POST /users/{id}/google-identity` | `user:manage`；撤销与可信身份绑定 |
| `GET /roles` | `user:manage`；当前角色权限矩阵 |

以上路径统一带 `/api/v1` 前缀。租户会话/RLS、复合租户外键及服务端权限验证均保留，不以隐藏按钮代替鉴权。
