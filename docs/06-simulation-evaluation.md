# 仿真评估方案

## 为什么必须做仿真

比赛评委真正关心的不是系统有没有覆盖所有电商后台功能，而是智能方案是否比传统方案更好。因此本项目把“证明有效”作为核心交付：用滚动仿真比较传统独立备货和智能库存池方案。

## Baseline：传统独立备货

传统方案假设各国家仓独立计划：

- 每个海外仓只看本仓销量和库存。
- 使用最近销量均值估计未来需求。
- 使用固定安全库存。
- 不做全球库存池优先级分配。
- 本地仓缺货时不主动跨仓履约。

这个 baseline 简单、清晰，适合作为比赛对照对象。

## 智能方案

智能方案使用以下闭环：

```text
AI需求预测 -> P80/P95需求分布 -> 补货点与目标库存 -> 全球库存池分配 -> 履约仓选择/跨仓调拨 -> 仿真反馈
```

它不是只优化预测误差，而是把预测结果转化为库存动作和履约动作。

## 滚动仿真流程

```text
Day 1: 根据历史销量、库存和在途数据生成补货计划。
Day 2: 仿真真实销量发生，库存减少。
Day 7: 系统重新预测、重新补货、重新分仓。
Day 8-90: 按周滚动执行和评估。
```

当前原型默认仿真 90 天，需求情景由历史销量、周末波动、促销峰值和增长趋势组合生成。

## 评估指标

| 指标 | 含义 | 评委容易理解的表达 |
| --- | --- | --- |
| 缺货率 | 有需求但无库存的比例 | 能不能少断货 |
| Fill Rate | 需求被库存满足的比例 | 用户能不能买到 |
| 平均配送时效 | 下单到送达时间 | 是否更快 |
| 平均库存 | 仿真期每日库存均值 | 是否少压货 |
| 库存周转天数 | 平均库存 / 日均销量 | 是否更健康 |
| 跨仓调拨成本 | 海外仓之间移动库存成本 | 是否调得过度 |
| 总利润 | 毛利 - 物流 - 仓储 - 缺货损失 | 是否真的赚钱 |

## 当前仿真结果

运行：

```bash
PYTHONPATH=src python -m overseas_inventory.demo
```

当前样例数据下，90 天仿真结果会写入：

- `output/replenishment_plan.md`
- `output/replenishment_plan.json`
- `output/dashboard.html`

结果摘要：

| 指标 | 传统独立备货 | 智能库存池方案 |
| --- | ---: | ---: |
| Fill Rate | 0.8140 | 1.0000 |
| 缺货率 | 0.1860 | 0.0000 |
| 平均配送时效 | 3.58 天 | 2.12 天 |
| 平均库存 | 10137.20 件 | 24967.82 件 |
| 总利润 | 127601.74 | 150115.58 |

当前样例中，智能方案为保障满供货率和更短履约时效提高了安全库存水位，因此平均库存高于传统方案。项目汇报时应明确这是服务水平、库存资金和利润之间的可配置权衡，避免表述为所有成本指标同时下降。

## 答辩表达

不要只说“预测更准确”，要说：

> 我们用仿真证明，预测进入补货和分仓决策以后，能把缺货风险、履约时效、库存资金和利润放到同一个决策框架里权衡。这才是供应链系统的业务价值。
