# 实施路线

## 阶段 1：方案与原型

目标：完成系统设计和最小可运行闭环。

交付：

- 项目说明、需求说明、系统设计、算法方案。
- 样例海外仓网络和 SKU 数据。
- 可运行的预测、补货、分仓原型。
- 自动测试覆盖关键约束。

验收标准：

- 能生成 SKU-仓维度补货建议。
- 能从全球库存池生成分仓计划。
- 分配结果不超过库存池可分配量。
- 输出结果可被人工阅读和系统解析。

## 阶段 2：业务数据接入

目标：将样例数据替换为真实业务数据。

任务：

- 接入订单销量数据。
- 接入库存、在途和已分配库存数据。
- 接入采购、供应计划、促销日历和物流成本数据。
- 建立 SKU、仓库、运输链路主数据维护机制。

验收标准：

- 每日自动生成预测输入表。
- 数据异常能被识别并进入人工处理队列。
- 每轮计划能追溯输入数据版本。

## 阶段 3：模型增强

目标：提高预测准确性和分配质量。

任务：

- 加入促销、广告、价格、平台活动、节假日等特征。
- 建立预测误差监控。
- 对不同品类选择不同预测模型。
- 引入仓容、资金、运输方式和采购周期约束。

验收标准：

- 预测误差按 SKU、区域、品类分层监控。
- 低置信度 SKU 能触发人工复核。
- 分配计划能解释主要约束和取舍。

## 阶段 4：决策驾驶舱与协同

目标：让供应链计划员可视化使用系统。

任务：

- 建立缺货预警、库存池水位、仿真对比和补货审批页面。
- 支持计划员调整建议数量并记录原因。
- 输出采购建议、调拨建议和发运计划。
- 建立计划采纳率和执行反馈。

验收标准：

- 计划员能在一个界面查看补货、分仓、缺口和原因。
- 审批与调整结果能回写系统。
- 系统能比较建议值、审批值和实际执行值。

## 主要风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 数据质量不足 | 销量、库存或在途数据延迟 | 建立数据校验和异常队列 |
| 预测过度自动化 | 低置信度 SKU 被错误补货 | 设置人工审批阈值 |
| 库存池被快速耗尽 | 热销区域吃掉全部库存 | 设置保留量和服务等级策略 |
| 单一成本导向 | 只追求低物流成本导致缺货 | 同时纳入服务、利润和缺货风险 |
| 业务不信任模型 | 建议看似合理但不可解释 | 输出补货原因、指标和版本记录 |

## 推荐下一步

1. 用真实 SKU 和海外仓数据替换 `data/sample_network.json`。
2. 增加一个 `configs/policy.json`，把服务等级、权重和审批阈值参数化。
3. 生成一份适合汇报的 PPT 或课程设计正文。
4. 搭建 Web 控制台，展示补货建议和库存池分配计划。
