# 电商、海外仓与物流 SOP 操作手册

更新：2026-11-20，Asia/Shanghai。适用当前 v0.12 实现；本文提供作业顺序和交接条件；Mock与图示用于演练，真实商家验收另留租户级证据。

## 1. 先确定谁持有事实、谁有权限

岗位是业务分工，角色是系统权限。仓库、货代提供的实物凭据，由获授权账号写入或由已配置的客户 WMS/ERP 连接回读；不能为了录入方便给全部外部人员管理员权限。

| 作业 | 建议角色 | 必须交接的内容 |
| --- | --- | --- |
| 租户和成员初始化 | 运维 + `TENANT_ADMIN` | 租户、可信 Google `sub`、成员及角色；默认无自助入驻 |
| 数据接入、映射、源对账 | `INTEGRATION_ADMIN` | 源端字段、权限、时间/数量口径、完整批次、独立导出及异常修正 |
| 预测、方案与运营假设 | `PLANNER` | 预测证据、策略、场景、数量依据和风险；无审批发布权限 |
| 补货审批、发布、人工执行/结算 | `APPROVER` | 审核记录、可用库存、实物证据与匹配快照；模型/BOM/运营假设按对应异人规则审批 |
| 观察与复盘 | `VIEWER` 或上述授权岗位 | 只读查看库存、计划和数据；修改和审批需其他明确授权 |

人工执行与结算端点使用 `plan:release`，仅有连接管理权限不能提交。当前业务 API 对受限地点账号会明确拒绝；不要把已有范围字段理解成完整的细粒度仓库工作台。客户之间由租户、RLS和复合外键隔离，同一3PL的多个客户不能未经授权共享数据、库存或训练样本。

## 2. 八步作业表

触发条件表示业务节拍，不是系统承诺的处理时长。每日独立预测调度需显式启用、设定租户当地签发小时，并确保数据就绪；发运/收货按实际事件更新，不能预先把计划值当成实际值。

| **08 等待实绩成熟并复核模型与运营效果**<br>预测目标窗口成熟后；不阻塞下一轮计划 | 计划员 / 经营负责人；另一成员批准模型晋级<br>「预测与模型、效果评估、运营协同」 | 同窗口比较均值与候选；分开校准和前向验证，复核运营 FVA。<br>**交接：**成熟评估、偏差与覆盖记录；满足门槛才进入晋级审批。 | **放行：**未成熟/缺失/删失窗口不报收益；存量成绩不能证明新品冷启动有效。<br>**异常：**样本不足或相对基线退化 → 保持候选/回退；不自动换模或承诺收益。 |

两条闭环分开运行：

- **运营闭环：**01–07；最终执行、必要双端库存结算通过后关闭活动计划，再开始下一轮。发运后仍保留相应库存扣减，直到权威新快照明确反映该单据并通过结算。
- **模型闭环：**03签发预测，08等待目标窗口成熟，再评分、校准和前向验证。没有成熟标签时显示等待，不阻塞下一轮经营计划，也不生成虚假提升。

## 3. 按行业走完整流程

### 3.1 Amazon / TikTok 跨境卖家与品牌商

1. **确认账户与实体。**按商家、市场创建连接，接入前先导入SKU和仓库映射。Mock显式授权后同步；切换真实商家前需具备审核权限与逐市场样例，不能把市场目录存在当成已经联调。
2. **确认需求和实物库存的主人。**批准各仓/渠道的需求来源，以及各仓库存与在途来源。同一销量不能把平台和ERP重复相加；平台库存与海外仓快照也不能直接相加代替来源规则。套组需要销售件/基础件口径与已发布BOM。
3. **选择补货所需的预测。**在「预测与模型」新建独立预测，查看mean28及候选。需要经营滞后和新品时，先在「经营信号与新品」配置来源/渠道、指标版本、上新事件与公开映射；缺渠道会提示修正，不自动猜测。
4. **审查业务假设和方案。**活动等运营调整先由另一成员批准并冻结为场景；选择匹配的保护期策略和预测证据，再生成影子计划。核对装箱、库存、运输L/L+R和到货前缺口，不仅比较总建议量。
5. **受控执行。**完成真实试点验收和适用模型门禁后，结束影子活动计划，另建执行计划并重新审核。发布后向仓库交接单据/行号、目的仓、数量和外部引用，按06–07完成执行与库存结算。
6. **成熟复盘。**同一SKU/仓、签发、周期和实际值比较模型与均值；运营FVA只比较同一成熟窗口。新品同龄先验不因存量成绩通过而获得真实执行权限。

Amazon Business Reports、广告分析与TikTok流量/广告报表的真实权限、异步报表及逐市场口径验收仍未完成。本期经营指标先通过明确契约的CSV/REST及Mock接入，不能假定点击一次平台授权就获得全部经营数据。

### 3.2 商贸分销与多仓零售

1. 不依赖平台数据时，以ERP销售、WMS库存和采购/在途为来源，从CSV/XLSX或REST开始；仍需租户认证、SKU/仓映射、完整批次和独立对账。
2. 确认一个库存池和目的仓，以及需求业务日、单位、时区、已分配量与未收采购口径。低销量、缺失和缺货删失分开记录，不用零覆盖所有异常。
3. 按03–05发行预测、生成区域仓补货建议并审核。供应商和资金等约束仅按实际配置生效，不把缺失配置当作已验证无限供给。
4. ERP/WMS继续承担采购入库和仓内作业；本系统通过约定单据引用关联累计执行，导入执行后快照，完成库存结算和计划关闭。
5. 财务结算、完整退货账务、多级制造MRP或供应商真实产能不在当前闭环内，需要单独接口与事实模型。

### 3.3 自有WMS、海外仓与3PL

1. 先确认服务客户和对应租户；客户授权范围内的店铺需求、库存池、目的仓、仓代码与SKU映射必须一致。只有仓储库存数据、缺少可信需求和来源契约时，不直接输出“生产可执行”的补货方案。
2. 提供完整库存、源版本、业务时钟和独立导出；遇到缺SKU、缺仓、部分分页或对账差异时，先在源端修正再重读。关闭差异处置只关闭工作流，不替代独立对账。
3. 按已发布计划在WMS完成拣选、打包、出库、接收；通过标准REST回读或凭据交给授权审批员登记。每次回传的是**累计数**，不是本次增量。
4. 新快照必须能证明已经反映相同执行引用的发运/收货/取消。源端发运扣减结算与目的仓收货结算分开验证；旧库存不能再次被分配。
5. 最终执行完成、必要双端结算通过后，由有权限成员关闭计划。仅创建了调拨单、只有源仓出库或运输仍在途时，不能提前关闭。

### 3.4 货代、干线与尾程承运协同

1. 与货主/仓库约定运输方式、提前期及到货信息的口径，交给有权限的成员维护。补货按各路线的L和L+R核对，不能把所有运输方式使用同一周期。
2. 订舱、干线调度和包裹运输在外部TMS/承运系统完成；本系统没有专用承运商API、运价采购或车辆排程。
3. 本系统的实物记录按客户单据/行和预占关联累计发运、收货、取消。承运商物流轨迹不能不经口径映射直接当成仓库收货；回传来源要与已批准执行契约一致。
4. 延误或ETA未知进入「库存风险」并调查；回读失败不释放预占，单据创建结果不明只查单。需要退货时补独立事实，不能把累计发运/收货数倒退。
5. 收货后仍需仓库执行后快照与独立清单，按07完成库存结算。承运签收不是财务结算，也不直接替代仓内库存对账。

## 4. 最小交接数据

| 交接物 | 最少要确认的内容 | 缺失时的处理 |
| --- | --- | --- |
| 来源与批次 | 租户、账户/市场、连接、流/范围、源版本、时间、完整性 | 隔离、补映射或重新读取；不把部分批次当成完整库存 |
| 经营与上新 | SKU/仓、渠道、当地业务日、指标/单位/币种/版本、覆盖状态；上新实体与同类群组 | 不使用不明口径特征；缺失不填零；新品供体不足明确回退 |
| 预测 | 输入ID、检查点/签发时刻、模型与代码、SKU/仓、目标日期、周期、轨迹/分位 | 取新证据；历史下载不倒填为过去已知；未校准分位不作履约承诺 |
| 计划与审批 | 冻结预测/场景、策略、库存水位、运输/到货、建议/最终数量、审核依据 | 数据或映射变化需重算；一个租户先结束旧活动计划 |
| 实物执行 | 来源连接、原单据/行、`external_ref`、单调`source_version`、累计发运/收货/取消、`is_final`、发生时刻和凭据 | 拒绝冲突、倒退或错单据；保留扣减和待处理状态 |
| 库存结算 | 执行后源/目的权威完整批次、独立清单、匹配的`execution_refs`和结算依据 | 等待另一端或补新快照；不删除预占掩盖差异 |
| 复盘 | 原冻结预测、成熟实际修订、同目标窗的基线/候选或批准运营场景 | 未成熟、缺失、删失窗口排除，不自报误差或收益 |

对预占数量Q，执行约束为 `shipped + cancelled <= Q`、`received <= shipped`；最终执行要求 `received + cancelled == Q`。接口字段、结算顺序和JSON例子见[执行契约](16-production-closure-and-auth.md#4-预占执行与结算)，经营/公开信号见[v0.12数据契约](23-commerce-coldstart-and-public-signals.md)。

## 5. 先做影子演练，再安排真实试点

| 验收动作 | 应看到的结果 | 证据 |
| --- | --- | --- |
| 创建租户与两类成员 | 计划员不能批准自己无权批准的业务；未绑定Google subject不能仅靠同邮箱登录 | 成员/身份绑定与权限记录 |
| 导入主数据和完整批次 | 未映射项隔离，修复后可重放；完整源能独立对账 | 批次、映射、隔离与matched记录 |
| 故意制造一条对账差异 | 差异可认领/修复/复核；仅关工单不能绕过执行门禁 | 原对账、新独立清单及处置依据 |
| 发行预测并生成影子计划 | mean28/候选/当前冠军配对；影子不创建实物预占或单据 | 预测ID、输入/代码摘要、影子计划 |
| 历史不足或新品无足够供体 | 显示回退/阻止原因，不假造新品命中率或执行资格 | 特征与生命周期证据 |
| 在隔离Mock环境完成执行演练 | 审核、预占、累计量、独立快照、双端结算、关闭依次完成 | 执行引用、源/目的批次、结算和关闭记录 |
| 目标窗未成熟时评分 | 明确等待/排除，无虚构MAE或收益 | 成熟评估的排除原因 |
| 真实账户/仓库上线申请 | 完成逐市场/仓库契约、长期对账、业务UAT、恢复/容量和适用模型验证后评审 | 对应租户的实际验收记录，不能用本仓库合成记录替代 |

真实店铺/仓库、模型效果、货代/承运接口和容量验证应分别登记范围。开关开启只提供技术入口，不等于完成验收。测试环境可按[浏览器验收脚本](17-production-workspace-integration.md#真实浏览器流程)复现；生产默认不启用测试供应商或测试路由。
