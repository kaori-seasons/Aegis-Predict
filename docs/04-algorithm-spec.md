# 算法方案

## 1. 需求预测

当前原型已从单一移动平均升级为真实训练的 `LightGBM / XGBoost / RandomForest` 机器学习集成预测管线。系统会把每个 SKU-海外仓的 180 天销量切成滚动监督学习样本，提取滞后销量、滚动均值、波动率、趋势、星期周期、SKU 编码、仓库编码、广告、促销、季节、平台活动和价格指数等特征，再训练树模型预测未来日均需求。输出不是单一销量数字，而是 P50/P80/P95 分位需求，用于把预测结果转成补货安全线。

核心输出：

- `daily_rate`：未来周期的预测日均销量。
- `horizon_units`：预测周期总需求。
- `p50_units`：中位需求预测。
- `p80_units`：偏安全的补货需求线。
- `p95_units`：高服务水平需求线。
- `volatility`：历史销量波动率。
- `confidence`：综合销量波动、训练样本量、可用模型数量和市场信号质量的简化置信度。

模型启用策略：

- 部署环境安装 `.[ml]` 后，优先启用 LightGBM、XGBoost 和 scikit-learn RandomForest。
- 如果某个库缺失或二进制环境不兼容，系统会跳过该模型并记录在 `feature_notes`。
- 如果外部 ML 库都不可用，系统启用内置纯 Python 随机森林兜底，保证比赛演示和学生上传流程仍然可运行。
- 后续可继续扩展 Prophet/ARIMA 或 Temporal Fusion Transformer，用于更强的季节性建模和跨 SKU 深度时序学习。

## 2. 库存位置

库存位置用于判断一个仓在未来补货周期内是否安全：

```text
库存位置 = 现货库存 + 在途库存 - 已分配库存
```

该指标比单纯现货库存更适合跨境补货，因为海外仓的在途周期较长，已发运但未到仓的货物会影响真实缺口。

## 3. 安全库存与补货点

系统按服务等级配置安全库存系数：

```text
安全库存 = 服务等级系数 * 需求波动率 * sqrt(运输提前期)
补货点 = 预测日均需求 * 运输提前期 + 安全库存
```

当库存位置低于补货点时，系统认为存在缺货风险；当库存位置低于目标库存时，系统生成补货建议。

目标库存使用 P80 需求作为比赛版安全线：

```text
目标库存 = P80预测周期需求 + 安全库存
建议补货量 = max(0, 目标库存 - 库存位置)
```

建议补货量按 SKU 包装数向上取整，保证发运计划符合箱规。

## 4. 紧急度评分

紧急度用于判断补货需求是否需要优先进入库存池分配：

```text
缺货压力 = max(0, 补货点 - 库存位置) / 补货点
紧急度 = 缺货压力 * 0.82 + 预测风险 * 0.18
预测风险 = 1 - 预测置信度
```

紧急度越高，说明该仓越可能在运输提前期内发生缺货。

## 5. 库存池分配优先级

库存池不是平均分货，而是一个带目标函数和约束的分仓优化问题。比赛材料中可以用以下变量表述：

```text
x[SKU, 仓库] = 某 SKU 分配到某海外仓的数量
r[SKU, 仓库] = 从国内补货到某海外仓的数量
t[SKU, 源仓, 目标仓] = 跨海外仓调拨数量
f[订单区域, 仓库] = 某区域订单由哪个仓履约
```

优化目标：

```text
最小化总成本 = 国际头程成本
             + 海外仓储成本
             + 尾程配送成本
             + 缺货惩罚成本
             + 跨仓调拨成本
             + 滞销库存成本
```

当前原型使用 `scipy.optimize.milp` 把分仓数量建模为整数规划变量。每个变量表示某 SKU 通过某运输方式分配到某海外仓的包装数：

```text
x[SKU, 目标仓, 运输方式] = 分配包装数
```

目标函数将缺货紧急度、需求规模、尾程能力、利润贡献、运输时效、运输可靠性和单位物流成本合成为收益分数，并最大化总收益。实现上使用负收益作为 `milp` 的最小化目标。

当求解器不可用或没有可行发运变量时，系统才回退到可解释启发式优先级：

```text
优先级 = 缺货紧急度 * 0.48
       + 需求规模得分 * 0.22
       + 尾程履约得分 * 0.16
       + 利润贡献得分 * 0.14
```

若 SKU 属于高服务等级，再乘以服务权重。这样可以让高价值、高时效压力、高缺货风险的仓点优先获得库存池供给。

## 6. 分配约束

- 分配总量不能超过库存池可分配库存。
- 单仓分配量不能超过该仓建议补货量。
- 分配量需要符合 SKU 包装数。
- 未满足部分进入采购或跨仓调拨队列。
- 仓库容量、单日入仓处理能力、采购可用量、资金预算和运输方式上限是 MILP 硬约束。
- 当前原型已加入采购可用量、资金预算、海运/空运、仓容上限、单日入仓能力和审批状态。

## 7. 情景仿真

比赛评估不能只看预测 MAPE，而要证明库存决策更好。当前原型内置 90 天滚动仿真：

```text
第 1 天：根据历史销量和当前库存生成补货/分仓计划。
第 2 天：真实销量发生，库存变化。
第 7 天：重新预测、重新补货、重新分仓。
循环到第 90 天。
```

对比对象：

- 传统方案：各国家仓独立备货，按最近销量均值和固定安全库存补货。
- 智能方案：全球库存池 + P80 预测 + 补货优化 + 分仓/跨仓履约。

评估指标：

- 缺货率。
- 订单满足率 / Fill Rate。
- 平均配送时效。
- 平均库存。
- 库存周转天数。
- 跨仓调拨成本。
- 总利润。

## 8. 原型与真实系统的差异

当前原型强调可解释性和方案验证，已经引入轻量整数规划求解器。真实系统可进一步加入：

- OR-Tools 或商用求解器，支持更大规模 SKU、仓网和运输批次。
- 铁路、卡航、海外仓间调拨等多路径选择。
- 缺货损失、滞销损失、退货成本和平台处罚成本函数。
- 跨仓调拨的路径和成本。
- 自动补货审批阈值和多级审批策略。
